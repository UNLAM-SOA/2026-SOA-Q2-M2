# PowerShare: circuito fisico y Node-RED

El sketch conserva la maquina de estados y los comandos Serial originales.
La adaptacion agrega MQTT y usa las conexiones y conversiones del banco de pruebas.
Toda la logica esta en sketch.ino; el unico archivo auxiliar es config.local.h,
con las credenciales de red.

## Arduino IDE

Usar el paquete de placas ESP32 de Espressif 3.x (el sketch ya usaba ledcAttach).
Instalar estas bibliotecas desde el gestor:

- Grove - LCD RGB Backlight (rgb_lcd.h, la misma del banco).
- ArduinoMqttClient 0.1.8.
- ArduinoJson 7.4.2 (API de la version 7).

Completar config.local.h; si falta, crearlo junto a sketch.ino con este contenido:

```cpp
#define POWERSHARE_WIFI_SSID "TU_WIFI_2_4_GHZ"
#define POWERSHARE_WIFI_PASSWORD "TU_CLAVE_WIFI"
#define POWERSHARE_MQTT_HOST "192.168.1.100" // IPv4 LAN de la PC con Mosquitto.
#define POWERSHARE_MQTT_PORT 1883
#define POWERSHARE_MQTT_USER "esp32"
#define POWERSHARE_MQTT_PASSWORD "ESP32_PASSWORD_DE_EDGE_CLOUD_ENV"
#define POWERSHARE_MQTT_PREFIX "powershare/esp32-01" // MQTT_PREFIX de Edge-Cloud/.env.
```

Este archivo esta ignorado por Git. Configurar SSID/clave de Wi-Fi de 2,4 GHz,
host MQTT = IPv4 LAN de la PC (no localhost), puerto 1883, usuario esp32,
clave = ESP32_PASSWORD y prefijo = MQTT_PREFIX de Edge-Cloud/.env.
setup.ps1 no configura esta carpeta: usa su propio config.local.h.

Abrir sketch/sketch.ino (la version activa), con config.local.h en esa misma
carpeta. La carpeta "sketch copy" conserva una copia anterior.
La compilacion y la carga a la placa se realizan desde Arduino IDE.

## Montaje y mediciones

| GPIO | Funcion |
|---|---|
| 35 | Grove Temp v1.1: promedio de 16 lecturas, beta 4275 y formula del banco. |
| 32 | ACS712 5 A: 200 muestras en mV, factor x10 y sensibilidad 185 mV/A. |
| 21 / 22 | SDA / SCL del Grove-LCD RGB. |
| 26 | Rele activo en HIGH: refrigeracion Creality, solo encendido/apagado. |
| 27 | LED verde: acompana a la salida de carga. |
| 25 | BC337: PWM de la carga Delta, 0-255. |

Al arrancar se apagan ambas salidas, se esperan 1,5 s y se calibra el cero del
ACS712 como en el banco. Encender USB, 5 V y 12 V y luego pulsar EN para calibrar
con las alimentaciones presentes. Si Serial indica ACS ERROR, revisar la
alimentacion y reiniciar. I_COMP_RELE queda en 0 A, igual al valor inicial del banco;
si se midio la compensacion con "comp", colocar ese resultado en la constante.

La tabla de estados original se conserva: DISPONIBLE y DESHABILITADO apagan ambas
salidas; ACTIVO enciende la carga; ENFRIAMIENTO mantiene la carga y enciende el rele.
Se entra a enfriamiento a 50 C y se vuelve a ACTIVO a 30 C. A 75 C se pasa a
DESHABILITADO, que tambien apaga la refrigeracion, como hacia el sketch original.
Las salidas de las transiciones se aplican en CONTINUE, como antes.

El saldo inicial es 0 Wh y se pierde al reiniciar. Se descuenta en ACTIVO y
ENFRIAMIENTO: 12 V x corriente x horas reales x 60. Se conserva el factor x60
para la demostracion; cambiar FACTOR_ACELERACION a 1 para tiempo real.
Con corriente <= 0,2 A no se descuenta y, luego de 10 s, se finaliza el uso.

## Comandos y MQTT

Monitor Serie a 115200, con nueva linea:

| Comando | Accion |
|---|---|
| c <Wh> | Recargar saldo positivo. |
| a / f | Autorizar / finalizar uso. |
| d / h | Deshabilitar / habilitar. |
| p <0..100> | Configurar el porcentaje entero de PWM de la carga Delta. |
| t <C> | Simular una temperatura entre -40 y 125 C (admite decimales). |
| t real | Volver a leer el sensor Grove. |

p funciona por Serial y MQTT. Arranca en 100 %; en ACTIVO/ENFRIAMIENTO
se aplica inmediatamente y en los otros estados se guarda para el proximo uso.
El porcentaje configura el duty cycle, no una corriente o potencia exacta:
el consumo sigue midiendose con el ACS712. p 0 apaga la carga y puede finalizar
el uso por corriente baja a los 10 s. La refrigeracion Creality usa rele y
mantiene su control automatico de encendido/apagado.

t es un comando local por Serial, para pruebas. La temperatura fijada se usa
en la FSM, LCD y telemetria hasta enviar t real o reiniciar; al arrancar siempre
se usa el sensor fisico. temperatureSimulated en la telemetria indica la fuente.
No se inyectan transiciones: la deteccion normal de zonas procesa el valor.
Los comandos y cambios de fuente se aplican desde la cola de la FSM.

Ejemplo de prueba (enviar cada linea y esperar la confirmacion/transicion):

```text
t 25
p 60
c 10
a
t 50
t 30
t 75
t real
h
```

Con corriente mayor que 0,2 A, a inicia ACTIVO con PWM 153/255. t 50 lleva a
ENFRIAMIENTO; t 30 vuelve a ACTIVO; t 75 pasa a DESHABILITADO. t real restaura
la lectura fisica, pero el estado DESHABILITADO requiere h, como antes.
Entre 30 y 50 C se conserva el estado termico anterior (histeresis).
Se rechazan porcentajes fuera de rango o fraccionarios, temperaturas fuera de
rango, NaN, infinitos y argumentos adicionales. Ninguno de estos ajustes se
guarda al reiniciar.

Con el stack iniciado, publicar en powershare/esp32-01/app/commands para pasar
por Node-RED. Usar QoS 1 y Retain desactivado; no hace falta enviar id:

{"command":"c","wh":10}
{"command":"a"}
{"command":"p","percent":50}
{"command":"f"}
{"command":"d"}
{"command":"h"}

Node-RED genera el id y lo incluye en el comando enviado al ESP32, la confirmacion
y el historial. Cada envio sin id es una nueva accion, incluso si repite contenido.
Se puede seguir enviando un id explicito para identificar un reintento.
Para comunicacion directa sin Node-RED, publicar en device/commands con id,
por ejemplo {"id":"directo-1","command":"p","percent":50}.

El comando MQTT p acepta un porcentaje entero de 0 a 100. Arranca configurado
en 100 %. En ACTIVO/ENFRIAMIENTO cambia el PWM de la carga; en otros estados
guarda el porcentaje para la proxima autorizacion, sin encender la carga.

El ESP32 publica device/status (online y Last Will offline, retained),
device/telemetry cada segundo y al resolver comandos, device/ack y device/events.
Node-RED reenvia datos a app/*. Se mantienen los nombres y tipos del contrato:
loadOn indica PWM de carga > 0; coolerPwm es 255 con el rele encendido y 0 apagado;
loadPwm informa el PWM real del Delta (0-255) y loadPercent el porcentaje solicitado.

La red funciona en una tarea separada de la FSM. Se rechazan comandos retained y
se recuerdan en RAM los ultimos 32 ids procesados para evitar recargas duplicadas.
Al reiniciar se pierden saldo y cache. Ante un timeout, revisar telemetria y
confirmaciones antes de reenviar una recarga sin id o con otro id, porque suma de nuevo.

diagram.json conserva el circuito anterior de Wokwi como referencia; no representa
este montaje fisico ni sus bibliotecas. No usarlo para validar estas conexiones.
El stack se describe en ../../Edge-Cloud/INICIO-FISICO.md.

## Verificacion local

Desde esta carpeta, ejecutar tests/run.ps1 con g++ y Arduino CLI disponibles.
Usa ArduinoJson instalado mediante Arduino CLI y mocks de hardware; comprueba
comandos Serial, PWM por estado, temperatura simulada, umbrales y vuelta al sensor.
La compilacion para placa se puede verificar con:

arduino-cli compile --fqbn esp32:esp32:esp32 --build-path build/esp32 sketch
